# 软件发布演练平台（本地虚拟实例）

Go 负责发布状态机与持久化，React 负责展示操作过程。所有“实例”都是本地虚拟记录，**不实际部署任何服务**，也不包含任何仓库自动执行逻辑。

## 能力

- **按批次更新**：发布时按百分比把实例切分为多个批次，逐批推进，支持自定义批次比例。
- **健康观察**：每批更新后进入观察窗口，聚合健康/不健康/待定计数；达到半批不健康阈值即快速失败，窗口结束仍有未知结果也按失败处理。
- **失败回退**：自动生成独立的**回退批次**（按发布波次逆序），把已更新实例明确送回基线版本；更新失败、从未落到新版本的实例不会被重复回退。
- **取消语义**：取消后立即停止扩批；已更新实例通过回退批次获得清楚归宿。
- **代际令牌（防迟到误归）**：每次更新/回退生成 generation token，健康探针结果必须匹配实例当前代际才被采纳；实例已经进入下一版或回退后，迟到结果被丢弃并记录 `probe_stale_discarded` 事件。
- **真实进度可刷新/可重启恢复**：所有状态转换先持久化（临时文件 + rename 原子写），刷新页面即看到真实进度；回退过程中中断，重启后按已持久化的回退计划继续，不重复规划。
- **独立存档**：版本、实例、发布批次分别保存在独立 JSON 文件：
  - `data/versions.json`
  - `data/instances.json`
  - `data/batches.json`（发布批次与回退批次）
  - 另有 `releases.json`、`events.json`、`faults.json`

后续要加入更多发布策略时，在创建发布处扩展 `strategy` 与批次生成逻辑即可，批次始终独立存档。

## 运行

构建前端（产物输出到 web/dist，会被 Go 二进制 embed）：

    cd frontend && npm install && npm run build && cd ..

启动后端（默认 :8080，状态写入 ./data）：

    go run . -addr :8080 -data ./data

浏览器打开 http://localhost:8080 。

前端开发模式（热更新，API 代理到 8080）：

    cd frontend && npm run dev

## 页面操作

- 顶部选择演练场景并“播种”：
  - **半批失败**：第一批 50% 节点探针不健康，触发回退；
  - **健康发布（可中途取消）**：观察扩批与取消归宿；
  - **迟到健康结果**：探针在观察窗口之后才返回，核对它不会被归到下一版；
  - **更新失败回退**：部分实例更新动作直接失败。
- 设置批次百分比（逗号分隔，合计 100）后开始发布；可随时取消、暂停/继续。
- 页面每 600ms 轮询真实状态，也可手动刷新。

## 自动化核对（不部署服务）

    go test ./...
    cd frontend && npm run build   # 含 tsc 类型检查

`internal/engine` 用确定性虚拟时钟（`Engine.Advance`）覆盖：

- 半批失败 → 停止扩批 → 全部回退到基线；
- 中途取消 → 已更新实例有清楚归宿，未开始批次保持等待；
- 迟到健康结果被丢弃且不会污染下一版/当前版状态；
- 回退进行中“崩溃”后，用新引擎重新打开同一数据目录，刷新即见真实进度并继续完成回退；
- 更新失败即回退；版本/实例/批次磁盘文件相互独立。
